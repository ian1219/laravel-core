In one sentence

Eloquent lets you build database queries by chaining readable PHP methods, then turns them into safe SQL for you.

🍔It's like ordering at a burger counter: "a burger, no onions, extra cheese, to go". You list what you want step by step, and the kitchen (the database) gets one precise order slip (the SQL).

Why it matters

Most of your app is reading and writing data

📖

Readable code

Post::where('views', '>', 100)->latest()->get() reads almost like English.

🔒

Safe by default

Values are sent as bound parameters, which protects you from SQL injection without extra effort.

♻️

Reusable filters

Query scopes give common conditions a name, like Post::published(), so you write them once.

The big picture

Build up, then fetch

1️⃣

One model

find(), first(), findOrFail() return a single Post (or null).

📚

Many models

all() and get() return a Collection, a supercharged array of Post objects.

📄

A page of models

paginate(10) returns 10 posts plus everything needed for page links.

Step by step

Query the blog's posts

Each step shows the PHP and the SQL it generates. Try them in php artisan tinker.

  1. Fetch everything, or one by id

    all() grabs every row. find() looks up a primary key and returns null if it's missing. findOrFail() throws an exception instead, which Laravel turns into a 404 page.

    
          $posts = Post::all();          // Collection of every post
          $post  = Post::find(7);        // Post or null
          $post  = Post::findOrFail(7);  // Post, or 404 page
        
    
          select * from `posts`;
          select * from `posts` where `posts`.`id` = 7 limit 1;

  2. Filter with where

    Pass a column, an optional operator and a value. Chain several where calls and they're joined with AND. Finish with get() for many rows or first() for one.

    
          $popular = Post::where('views', '>', 100)
              ->where('category_id', 3)
              ->get();

          $hello = Post::where('slug', 'hello-world')->first();

          $drafts = Post::whereNull('published_at')->get();
        
    
          select * from `posts` where `views` > 100 and `category_id` = 3;
          select * from `posts` where `slug` = 'hello-world' limit 1;
          select * from `posts` where `published_at` is null;

  3. Sort, limit and paginate

    orderBy() sorts by any column. latest() is shorthand for "newest created_at first". paginate() runs a count query plus a limited query, and reads the current page from ?page= in the URL.

    
          $titles = Post::orderBy('title')->take(5)->get();
          $newest = Post::latest()->first();
          $page   = Post::latest()->paginate(10);   // in a controller
        
    
          select * from `posts` order by `title` asc limit 5;
          select * from `posts` order by `created_at` desc limit 1;
          select count(*) as aggregate from `posts`;
          select * from `posts` order by `created_at` desc limit 10 offset 0;
        
    
          @foreach ($page as $post)
              <h2>{{ $post->title }}</h2>
          @endforeach

          {{ $page->links() }}  {{-- Previous / 1 2 3 / Next --}}

  4. Create, update and delete

    create() inserts a row and returns the new model (the columns must be in $fillable). To change a row, either set properties and save(), or pass an array to update().

    
          $post = Post::create([
              'title' => 'Hello World',
              'slug'  => 'hello-world',
              'body'  => 'My first post.',
          ]);

          $post->title = 'Hello, World!';
          $post->save();

          $post->update(['views' => 42]);
          $post->delete();
        
    
          insert into `posts` (`title`, `slug`, `body`, `updated_at`, `created_at`) values (?, ?, ?, ?, ?);
          update `posts` set `title` = ?, `updated_at` = ? where `id` = 1;
          update `posts` set `views` = ?, `updated_at` = ? where `id` = 1;
          delete from `posts` where `id` = 1;
    ℹ️ What are those ? marks?

    They're bindings. Eloquent sends your values separately from the SQL text, so a title like '; DROP TABLE posts; -- is stored as plain text, never executed.

  5. Name common filters with query scopes

    A local scope is a model method that adds conditions to a query. The classic way is to prefix the method name with scope, then call it without the prefix.

    
          use Illuminate\Database\Eloquent\Builder;

          // Classic style, works in every Laravel version
          public function scopePublished(Builder $query): void
          {
              $query->whereNotNull('published_at')
                    ->where('published_at', '<=', now());
          }

          public function scopeInCategory(Builder $query, int $categoryId): void
          {
              $query->where('category_id', $categoryId);
          }
        
    
          $posts = Post::published()->inCategory(3)->latest()->paginate(10);
        
    
          select * from `posts`
          where `published_at` is not null and `published_at` <= ? and `category_id` = ?
          order by `created_at` desc limit 10 offset 0;
    ℹ️ Laravel 12 alternative

    Newer Laravel 12 releases also accept a #[Scope] attribute on a protected function published(Builder $query) method, with no prefix. Both styles are called the same way: Post::published().

  6. Peek at the SQL yourself

    When a query misbehaves, look at what Eloquent actually built. toRawSql() returns the SQL with the bindings filled in, and dd() dumps it and stops.

    
          echo Post::published()->where('views', '>', 100)->toRawSql();
          Post::where('slug', 'hello-world')->dd();   // dump SQL + bindings, then stop
Common mistakes

Avoid this, do that

❌ Avoid

          $posts = Post::all()
              ->where('category_id', 3)
              ->take(5);

all() loads every post into memory first, then filters in PHP. Slow once you have thousands of rows.

✅ Do

          $posts = Post::where('category_id', 3)
              ->take(5)
              ->get();

Build the query first and call get() last, so the database does the filtering.

❌ Avoid

          $post = Post::find($id);
          return view('posts.show', ['post' => $post]);

If the id doesn't exist, $post is null and the view crashes with a confusing error.

✅ Do

          $post = Post::findOrFail($id);
          return view('posts.show', ['post' => $post]);

A missing post becomes a clean 404 page automatically.

💡 Pro tip: catch accidental heavy queries early

Install Laravel Debugbar or use Laravel Telescope locally. They list every query a page ran, so you'll spot slow or repeated queries before your users do.

Recap

Key takeaways

  • Chain where, orderBy and latest; nothing runs until get, first or paginate.
  • findOrFail() gives you a free 404 when a record is missing.
  • create(), update() and delete() handle writes; timestamps update automatically.
  • Values become bindings, protecting you from SQL injection.
  • Scopes like Post::published() turn repeated conditions into named, reusable pieces.
  • Use toRawSql() or dd() to see the SQL Eloquent generates.
