In one sentence

A controller is a class that groups the code answering related requests, so your route file stays a clean list of URLs.

🧑‍💼If routes are the receptionist, controllers are the department managers. The receptionist just says “billing questions go to Sam”. Sam then handles every billing request, and has the tools to do it.

Why it matters

Closures don't scale

📜

Readable routes

Twenty closures with logic inside make web.php hundreds of lines long. With controllers, each route is one line.

📦

Related code together

Everything about posts (list, show, create, edit) lives in one PostController.

💉

Free dependencies

Type-hint what you need in a method's parameters, and Laravel builds it and passes it in for you.

Step by step

Build a PostController

We'll keep using the blog. You don't need a database yet; we'll fake the data with arrays.

  1. Generate the controller

    Let Artisan write the boilerplate. Controller names are singular, PascalCase, and end in Controller.

    
          php artisan make:controller PostController
        
    
          <?php

          namespace App\Http\Controllers;

          use Illuminate\Http\Request;

          class PostController extends Controller
          {
              //
          }

  2. Add methods and point routes at them

    Each public method is an action. In the route, use the array syntax [Class::class, 'method']. Route parameters arrive as method arguments, matched by name.

    
          class PostController extends Controller
          {
              public function index()
              {
                  return 'All posts';
              }

              public function show(string $id)
              {
                  return "Post #{$id}";
              }
          }
        
    
          use App\Http\Controllers\PostController;

          Route::get('/posts', [PostController::class, 'index'])->name('posts.index');
          Route::get('/posts/{id}', [PostController::class, 'show'])->name('posts.show');
    💡 Group routes by controller
    
            Route::controller(PostController::class)->group(function () {
                Route::get('/posts', 'index');
                Route::get('/posts/{id}', 'show');
            });

  3. Pass data to a view

    Most actions end by returning a view. Pass data as an array, or use compact(), which builds the array from variable names.

    
          public function index()
          {
              $posts = [
                  ['id' => 1, 'title' => 'Hello Laravel'],
                  ['id' => 2, 'title' => 'Controllers are neat'],
              ];
              $heading = 'Latest posts';

              // same as ['posts' => $posts, 'heading' => $heading]
              return view('posts.index', compact('posts', 'heading'));
          }

          public function show(string $id)
          {
              return view('posts.show', ['id' => $id]);
          }

    In resources/views/posts/index.blade.php, $posts and $heading are now available. You'll style them in Blade Templates.

  4. Inject dependencies through parameters

    Dependency injection means “ask for what you need instead of creating it”. Type-hint a class in a method's parameters and Laravel's service container builds it and passes it in, alongside any route parameters.

    
          use Illuminate\Http\Request;

          public function search(Request $request)
          {
              $term = $request->input('q', '');

              return view('posts.search', ['term' => $term]);
          }

          // Route parameters and injected classes can be mixed:
          public function update(Request $request, string $id)
          {
              // $request is injected, $id comes from /posts/{id}
          }

    You'll see how this magic works in The Service Container.

  5. Single-action controllers with __invoke

    Some actions don't fit a group, like a homepage or “publish this post”. Give them their own invokable controller with one __invoke method.

    
          php artisan make:controller ShowHomepageController --invokable
        
    
          class ShowHomepageController extends Controller
          {
              public function __invoke()
              {
                  return view('home');
              }
          }
        
    
          Route::get('/', ShowHomepageController::class);   // no method name needed

  6. A peek ahead: resource controllers

    Almost every “thing” in an app needs the same seven actions: list, show, create form, store, edit form, update, delete. A resource controller generates all of them, and one route line registers them all.

    
          php artisan make:controller PostController --resource
        
    
          Route::resource('posts', PostController::class);

    The full story is in Resource Controllers.

Common mistakes

Avoid this, do that

❌ Avoid

          Route::get('/posts/{id}', 'PostController@show');

The old string syntax isn't checked by your editor and breaks silently when you rename a class.

✅ Do

          use App\Http\Controllers\PostController;

          Route::get('/posts/{id}', [PostController::class, 'show']);

The array syntax with ::class gives you autocompletion and “go to definition”.

❌ Avoid

          public function show(string $id)
          {
              $request = new Request();
              $term = $_GET['q'];
          }

Building the request yourself gives you an empty object, not the real incoming request.

✅ Do

          public function show(Request $request, string $id)
          {
              $term = $request->input('q');
          }

Type-hint it and let Laravel inject the current request.

💡 Pro tip: keep controllers thin

A healthy action is around 5–15 lines: read input, call a model or service, return a response. If one grows past that, move the logic out. See Service Classes.

🏋️ Try it yourself
  1. Create a PostController with index and show actions, and wire them to /posts and /posts/{id}.
  2. Make index pass an array of three fake posts to a posts.index view.
  3. Create an invokable AboutController for /about.
  4. Add a search action that injects Request and echoes back ?q=.
  5. Run php artisan route:list and check that each route shows its controller.
Recap

Key takeaways

  • Create controllers with php artisan make:controller NameController; they live in app/Http/Controllers.
  • Point routes at them with [PostController::class, 'method'].
  • Route parameters arrive as method arguments; return view('name', $data) to pass data.
  • Type-hint classes like Request and Laravel injects them automatically.
  • Use __invoke (--invokable) for single-job controllers, and --resource for full CRUD.
