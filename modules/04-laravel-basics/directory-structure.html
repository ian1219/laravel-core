In one sentence

Every Laravel project has the same folder layout, so once you learn it you can find your way around any Laravel app.

🏬It's like a supermarket chain. Every branch puts bread, dairy and checkouts in the same places, so you can walk into a store you've never visited and still find the milk.

The big picture

The Laravel 11+ skeleton

Laravel 11 slimmed the skeleton right down. If an older tutorial mentions app/Http/Kernel.php or app/Console/Kernel.php, those files are gone; their jobs moved into bootstrap/app.php.

Step by step

Tour the folders that matter

We'll follow the order a request travels: in through the route, into a controller, to a model, out through a view.

  1. routes/: the map of URLs

    routes/web.php lists every page URL. A fresh app has just one route, the welcome page. routes/api.php doesn't exist until you run php artisan install:api.

    
          <?php

          use Illuminate\Support\Facades\Route;

          Route::get('/', function () {
              return view('welcome');
          });

    Dive deeper in Routing.

  2. app/: your application code

    Everything in app/ uses the App\ namespace, and the folder path matches the namespace. So app/Models/Post.php is the class App\Models\Post. Composer autoloads it; you never require files by hand.

    
          php artisan make:model Post          # → app/Models/Post.php
          php artisan make:controller PostController   # → app/Http/Controllers/PostController.php

    As your app grows you'll add more folders here, such as Policies/, Jobs/ and Services/. Artisan creates most of them on demand.

  3. resources/views/: what users see

    Blade templates live here. Dots in a view name map to folders: view('posts.index') loads resources/views/posts/index.blade.php.

    
          return view('posts.index');   // resources/views/posts/index.blade.php

  4. database/: tables and test data

    Migrations are PHP files that describe your tables. They're version control for your database schema. A fresh app already has migrations for users, cache and jobs.

    
          php artisan make:migration create_posts_table
          php artisan migrate

  5. bootstrap/app.php: the app's wiring

    This short file configures how the app starts: which route files load, which middleware run, and how exceptions are handled. In Laravel 11+ this replaces the old Kernel classes.

    
          return Application::configure(basePath: dirname(__DIR__))
              ->withRouting(
                  web: __DIR__.'/../routes/web.php',
                  commands: __DIR__.'/../routes/console.php',
                  health: '/up',
              )
              ->withMiddleware(function (Middleware $middleware) {
                  //
              })
              ->withExceptions(function (Exceptions $exceptions) {
                  //
              })->create();

  6. public/ and storage/: the edges

    public/ is the only folder the web server exposes. It holds index.php (the front controller), plus images and built CSS/JS. storage/ is where Laravel writes things: logs in storage/logs/laravel.log, caches and uploaded files.

    💡 Something broke?

    Open storage/logs/laravel.log. The full error and stack trace is almost always there.

Common mistakes

Avoid this, do that

❌ Avoid

          vendor/laravel/framework/src/...  ✏️ edited

Files in vendor/ are overwritten on every composer install or update. Your changes will vanish.

✅ Do

          app/  config/  bootstrap/app.php  ✏️ edited

Customise behaviour from your own code, config files or service providers.

❌ Avoid

          Web server root → /var/www/blog

Pointing the server at the project root would expose .env, your source code and more.

✅ Do

          Web server root → /var/www/blog/public

Only public/ should be reachable from the internet.

💡 Pro tip: publish only what you need

Some config files and route files are hidden until you need them. Commands like php artisan config:publish and php artisan install:api add them to your project on demand.

🏋️ Try it yourself
  1. Open your blog project and find routes/web.php, resources/views/welcome.blade.php and app/Models/User.php.
  2. Run php artisan make:model Post and check where the file appeared and what namespace it uses.
  3. Visit /up in your browser. Find where that route is defined in bootstrap/app.php.
  4. Visit a URL that throws an error (e.g. a route returning view('missing')), then find the error in storage/logs/laravel.log.
Recap

Key takeaways

  • Daily folders: routes/, app/Http/Controllers, app/Models, resources/views, database/migrations.
  • bootstrap/app.php configures routing, middleware and exceptions; there are no Kernel files in Laravel 11+.
  • Folder paths in app/ match namespaces: app/Models/Post.php → App\Models\Post.
  • public/ is the only web-facing folder; storage/ holds logs, cache and uploads.
  • Never edit vendor/.
