What you'll build

A small online shop with a product catalog, a session cart, a checkout that creates orders and reduces stock, and queued confirmation emails, all organised with actions, DTOs, events and caching.

🛒This is the “final exam” project. Like a real shop, lots of things happen when someone pays: stock changes, an email goes out, the admin is told. Your architecture decides whether that stays tidy or turns into one 300-line controller method.

Features

What the finished shop does

Combines everything so far, plus Module 10 events, Module 13 queues and caching, and Module 14 architecture.

🛍️

Catalog

Browse products by category, with a cached “featured” list on the home page.

🛒

Cart

Add, update and remove items; the cart lives in the session.

💳

Checkout

Turns a cart into an order inside a database transaction, checking stock first.

📧

Queued emails

Order confirmations are sent in the background so checkout stays fast.

📣

Events

OrderPlaced triggers emails, stock alerts and cache clearing.

🧑‍💼

Admin area

Admins manage products and order statuses, protected by policies.

ℹ️ Store money as integers

Save prices in cents (1999 = $19.99) to avoid floating-point rounding errors. Copy unit_price onto each order item so old orders keep their price if a product changes later.

Build it

Build it milestone by milestone

This is the largest project. Commit after every milestone and keep your tests green as you go.

  1. Set up the project, auth and schema

    Create the app with a starter kit, then write migrations and models for categories, products, orders and order items, with relationships and factories.

    🧰 Starter Kits 🗄️ Migrations 🔗 Relationships 🌱 Factories & Seeders

  2. Admin product management

    Build a product CRUD with image upload under an /admin prefix. Protect it with a gate or policy that only allows admins.

    🛠️ Resource Controllers 🚦 Forms & Validation 🚪 Gates 🛡️ Policies

  3. Catalog pages with caching

    List products by category with eager loading. Cache the featured-products query on the home page, since it changes rarely but is read on every visit.

    
          $featured = Cache::remember('catalog.featured', now()->addHour(), fn () =>
              Product::where('is_featured', true)->with('category')->take(8)->get()
          );
    🗃️ Caching ⚡ Eager Loading & N+1

  4. A session cart behind a service class

    Wrap all cart logic in a CartService (add, update quantity, remove, total) so controllers never touch the session directly.

    
          public function add(Product $product, int $quantity = 1): void
          {
              $items = session('cart', []);
              $items[$product->id] = ($items[$product->id] ?? 0) + $quantity;
              session(['cart' => $items]);
          }
    🧠 Service Classes 📦 The Service Container 🍪 Sessions (How Authentication Works)

  5. Checkout with an action and a DTO

    Build a readonly CheckoutData DTO and a PlaceOrder action. Inside a transaction, lock the products, check stock, create the order and items, reduce stock, then fire an event.

    
          public function handle(User $user, CheckoutData $data): Order
          {
              $order = DB::transaction(function () use ($user, $data) {
                  $products = Product::whereKey(array_keys($data->items))
                      ->lockForUpdate()->get();

                  // check stock, create order + items, decrement stock ...
              });

              OrderPlaced::dispatch($order);

              return $order;
          }
    ⚡ Actions & DTOs 🔎 Eloquent Queries

  6. Events and listeners

    Create an OrderPlaced event with listeners for the confirmation email, a low-stock alert to admins, and forgetting the catalog.featured cache key.

    📣 Events & Listeners 🔧 Service Providers

  7. Queue the slow work

    Make the email listener implement ShouldQueue, switch QUEUE_CONNECTION to database, and run a worker. Checkout should now respond instantly.

    
          php artisan make:queue-table   # skip if the jobs table already exists
          php artisan migrate
          php artisan queue:work
    🧵 Queues & Jobs

  8. Customer orders and admin statuses

    Customers see only their own orders (an OrderPolicy); admins can move an order through pending → paid → shipped. Use a PHP enum cast for the status.

    🛡️ Policies 👑 Roles & Permissions 🧱 Models (casts)

  9. Test checkout end to end

    Feature-test the checkout route with Queue::fake() or Event::fake(), and unit-test PlaceOrder for the “not enough stock” case.

    
          Event::fake([OrderPlaced::class]);

          $order = app(PlaceOrder::class)->handle($user, $data);

          $this->assertSame(8, $product->fresh()->stock);
          Event::assertDispatched(OrderPlaced::class);
    🧪 Feature Tests 🔬 Unit Tests

  10. Organise and prepare for production

    Review your folders against the decision table and decide whether to group actions by area. Then run the production checklist: cache config, routes and views, and supervise the queue worker.

    🏛️ Structuring Large Apps 📚 Repository Pattern (when not to) 🚀 Production Optimisation

Definition of done

You're finished when…

  • A customer can browse, fill a cart, check out and see their order history.
  • Checkout runs in a transaction, never oversells stock, and stores prices as integer cents.
  • Controllers stay thin; cart and checkout logic live in a service, actions and readonly DTOs.
  • Confirmation emails are queued and sent by a worker, triggered by an OrderPlaced event.
  • Featured products are cached and the cache is cleared when it goes stale.
  • Tests cover checkout success, out-of-stock failures and authorization, and they all pass.
