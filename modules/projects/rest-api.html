What you'll build

A versioned JSON API for the blog (posts, comments and categories) that mobile apps and JavaScript frontends can use with Sanctum tokens, predictable errors, rate limits and a full test suite.

🔌A website is a restaurant with tables and menus. An API is the takeaway window: no decoration, just a clear menu (endpoints), a ticket system (tokens) and a rule about how many orders one customer can place per minute (rate limits).

Build it

Build it milestone by milestone

Use an HTTP client (Postman, Insomnia, Bruno or curl) alongside your tests. Always send Accept: application/json.

  1. Design the endpoints first

    Before writing code, write the table above for your own API: nouns in URLs, verbs in methods, and the status code each endpoint returns.

    🔌 REST Basics 🌐 How HTTP Works

  2. Install API routing and Sanctum

    One command creates routes/api.php, installs Sanctum and publishes its migration. Add the HasApiTokens trait to User.

    
          php artisan install:api
    📦 API Routes & Resources 🎟️ Sanctum Authentication

  3. Register, log in and log out

    Issue a token on login, check the password with Hash::check(), and delete the current token on logout.

    
          public function login(LoginRequest $request)
          {
              $user = User::where('email', $request->email)->first();

              if (! $user || ! Hash::check($request->password, $user->password)) {
                  throw ValidationException::withMessages(['email' => 'Invalid credentials.']);
              }

              return ['token' => $user->createToken($request->device_name)->plainTextToken];
          }
    🎟️ Sanctum Authentication 🔑 Hashing & Encryption

  4. Shape output with API Resources

    Create PostResource, CommentResource and UserResource. Never return raw models: resources hide columns like email and keep the format stable. Use whenLoaded() for relations.

    
          return [
              'id' => $this->id,
              'title' => $this->title,
              'slug' => $this->slug,
              'author' => new UserResource($this->whenLoaded('author')),
              'published_at' => $this->published_at?->toIso8601String(),
          ];
    📦 API Routes & Resources ⚡ Eager Loading & N+1

  5. CRUD endpoints with policies

    Use Route::apiResource() under a v1 prefix. Validate with Form Requests, return 201 on create and 204 on delete, and reuse the PostPolicy from Project 2.

    
          Route::prefix('v1')->group(function () {
              Route::apiResource('posts', PostController::class)->only(['index', 'show']);

              Route::middleware('auth:sanctum')->group(function () {
                  Route::apiResource('posts', PostController::class)->except(['index', 'show']);
              });
          });
    🛠️ Resource Controllers 🚦 Forms & Validation 🛡️ Policies

  6. Make errors predictable

    In bootstrap/app.php, make API exceptions always render as JSON, and return a consistent shape for 404s instead of an HTML page.

    
          ->withExceptions(function (Exceptions $exceptions) {
              $exceptions->shouldRenderJsonWhen(
                  fn (Request $request) => $request->is('api/*')
              );
          })
    🧯 Versioning & Error Handling 🔄 The Request Lifecycle

  7. Add rate limiting

    Define named limiters in AppServiceProvider::boot(): one per user (or IP for guests) for the whole API, and a strict one for login. Apply them with throttle: middleware and check the 429 response.

    
          RateLimiter::for('api', fn (Request $request) =>
              Limit::perMinute(60)->by($request->user()?->id ?: $request->ip())
          );
          RateLimiter::for('login', fn (Request $request) =>
              Limit::perMinute(5)->by($request->ip())
          );
    ⏱️ Rate Limiting 🧱 Middleware

  8. Filtering, sorting and pagination

    Support ?category=laravel&sort=-published_at&per_page=20. Whitelist sortable columns, cap per_page at 50, and return PostResource::collection($posts) to get links and meta automatically.

    🔎 Eloquent Queries 💉 SQL Injection & Mass Assignment

  9. Test every endpoint

    Use factories and Sanctum::actingAs() to test success paths, 401 without a token, 403 on someone else's post, 422 on bad input, and 429 when the limit is hit.

    
          public function test_guests_cannot_create_posts(): void
          {
              $this->postJson('/api/v1/posts', [])->assertUnauthorized();
          }

          public function test_authors_can_create_posts(): void
          {
              Sanctum::actingAs(User::factory()->create());

              $this->postJson('/api/v1/posts', [
                  'title' => 'Hello API',
                  'body' => 'First post',
                  'category_id' => Category::factory()->create()->id,
              ])
                  ->assertCreated()
                  ->assertJsonPath('data.title', 'Hello API');
          }

Definition of done

You're finished when…

  • Clients can register, log in for a token, use it as a Bearer header, and log out to revoke it.
  • Every response goes through an API Resource; no raw models or hidden columns leak.
  • Endpoints return the correct status codes: 200, 201, 204, 401, 403, 404, 422 and 429.
  • All errors on /api/* come back as JSON, never as an HTML page.
  • Rate limits are in place for the API and, more strictly, for login.
  • php artisan test passes, with tests for both success and failure on every endpoint.
