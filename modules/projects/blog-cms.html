What you'll build

A multi-author blog where users register, write posts with cover images, file them under categories and comment, while policies make sure nobody can edit someone else's work.

📰Think of a small newsroom: reporters write their own stories, editors can fix anyone's, and readers can only comment. Your job is to build the building and the security desk.

Features

What the finished app does

Builds on Project 1 and adds Modules 07–08, relationships from Module 05, and file uploads.

🔐

Accounts

Register, log in, verify email and reset passwords via a starter kit.

✍️

Author dashboard

Authors manage their own posts: drafts, publish, edit, delete.

🏷️

Categories & tags

Each post has one category and many tags.

🖼️

Cover images

Upload, validate, store and replace an image per post.

💬

Comments

Logged-in readers comment; authors can delete comments on their posts.

🛡️

Roles

Admins can edit anything; authors only their own posts.

Build it

Build it milestone by milestone

Each milestone should leave the app working. Commit after each one.

  1. Start with a starter kit

    Create the project and pick a starter kit so registration, login, email verification and password reset work on day one. Breeze is the classic, minimal option.

    
          laravel new blog-cms   # choose a starter kit when prompted
          php artisan migrate
    🔐 How Authentication Works 🧰 Starter Kits 📧 Email Verification & Password Reset

  2. Migrations and relationships

    Create the categories, posts, comments, tags and pivot tables with foreign keys. Define every relationship on the models and test them in Tinker.

    
          public function author(): BelongsTo
          {
              return $this->belongsTo(User::class, 'user_id');
          }

          public function tags(): BelongsToMany
          {
              return $this->belongsToMany(Tag::class);
          }
    🗄️ Migrations 🔗 Relationships

  3. Seed realistic data

    Write factories for each model and a seeder that creates 5 categories, 10 users and 50 posts with comments, so you can design pages with real-looking content.

    🌱 Factories & Seeders

  4. Public pages: list and read posts

    Build a paginated home page of published posts and a post page found by slug. Eager load the author and category to avoid N+1 queries.

    
          Post::published()->with(['author', 'category'])->latest('published_at')->paginate(10);
    📋 Create & Read 🔎 Eloquent Queries ⚡ Eager Loading & N+1

  5. Protect the author dashboard

    Put the post-management routes behind auth and verified middleware under a /dashboard prefix. Create posts with $request->user()->posts()->create(...).

    
          Route::middleware(['auth', 'verified'])->prefix('dashboard')->name('dashboard.')
              ->group(function () {
                  Route::resource('posts', Dashboard\PostController::class);
              });
    🚧 Guards & Protecting Routes 🛠️ Resource Controllers 🚦 Forms & Validation

  6. Write a PostPolicy

    Authors may update and delete only their own posts; admins may do anything (use before()). Call Gate::authorize() in the controller and @can in Blade to hide buttons.

    
          public function before(User $user): ?bool
          {
              return $user->is_admin ? true : null;
          }

          public function update(User $user, Post $post): bool
          {
              return $user->id === $post->user_id;
          }
    🚪 Gates 🛡️ Policies 👑 Roles & Permissions

  7. Upload cover images

    Add a file input (remember enctype="multipart/form-data"), validate it as an image, store it on the public disk, and delete the old file when replacing it. Run php artisan storage:link once.

    
          $request->validate(['cover' => ['nullable', 'image', 'max:2048']]);

          if ($request->hasFile('cover')) {
              $post->cover_path && Storage::disk('public')->delete($post->cover_path);
              $post->cover_path = $request->file('cover')->store('covers', 'public');
          }
    🚦 Forms & Validation ✏️ Update & Delete

  8. Categories, tags and comments

    Add a category filter page, sync tags with $post->tags()->sync($ids), and a comment form for logged-in users. Add a CommentPolicy so post authors can delete comments on their posts.

    🔗 Relationships 🛡️ Policies 🖌️ Blade Templates

  9. Lock down security basics

    Check every form has @csrf, post bodies are shown with {{ }} (never {!! !!} on user input), and models use $fillable so is_admin can't be mass-assigned.

    🔒 CSRF & XSS 💉 SQL Injection & Mass Assignment

  10. Test the rules that matter

    Write feature tests proving a guest is redirected to login, an author can't edit another author's post (403), and an upload stores a file (use Storage::fake('public')).

    🧪 Testing Basics 🧪 Feature Tests

  3. Generate a resized thumbnail for each cover in a queued job.

Definition of done

You're finished when…

  • Users can register, verify email, log in, and reset a forgotten password.
  • Authors manage only their own posts; admins can manage everything, enforced by policies (not just hidden buttons).
  • Posts have a category, tags, comments and an optional cover image that's validated and cleaned up on replace.
  • Listing pages run a fixed number of queries thanks to eager loading.
  • php artisan migrate:fresh --seed produces a realistic demo blog.
  • Feature tests cover authentication, authorization and uploads, and they all pass.
