In one sentence

Email verification proves a user really owns their inbox, and password reset uses that same inbox to let them back in when they forget their password.

📬It's like a building that posts a key to your registered address. Only the person who can open that mailbox gets the key, so the mailbox becomes your proof of identity.

Why it matters

The features every real app needs

✉️

Real, reachable users

Verification stops typos and fake sign-ups, and it makes sure your emails actually arrive.

🔑

People forget passwords

Without a reset flow, every forgotten password becomes a support ticket.

🎁

Mostly built for you

Starter kits ship both flows. You switch them on and configure mail.

The big picture

How a password reset works

Email verification follows the same pattern. After registering, the user gets an email with a signed URL (a link Laravel can tell hasn't been tampered with). Clicking it fills in the email_verified_at column.

Step by step

Switch it all on

These steps assume you installed a starter kit, which already contains the screens and routes.

  1. Send mail to the log while developing

    You don't want real emails going out from your laptop. With the log mailer, every email is written to storage/logs/laravel.log instead, so you can copy links straight out of it.

    
          MAIL_MAILER=log
          MAIL_FROM_ADDRESS="hello@blog.test"
          MAIL_FROM_NAME="${APP_NAME}"

    In production, switch to a real service, for example MAIL_MAILER=smtp with your provider's host, port, username and password. Or use a tool like Mailpit locally if you want to see emails rendered.

  2. Turn on email verification

    Make the User model implement the MustVerifyEmail contract. The import is already in the file, but commented out.

    
          <?php

          namespace App\Models;

          use Illuminate\Contracts\Auth\MustVerifyEmail;
          use Illuminate\Foundation\Auth\User as Authenticatable;
          use Illuminate\Notifications\Notifiable;

          class User extends Authenticatable implements MustVerifyEmail
          {
              use Notifiable;
              // ...
          }

    Now Laravel automatically sends a verification email when someone registers.

  3. Require verification with the verified middleware

    Add verified next to auth on routes that need a confirmed email. Unverified users are redirected to the “please verify your email” screen (the route named verification.notice).

    
          Route::middleware(['auth', 'verified'])->group(function () {
              Route::get('/dashboard', fn () => view('dashboard'))->name('dashboard');
              Route::resource('posts', PostController::class)->except(['index', 'show']);
          });

    Order matters: auth first (are you logged in?), then verified (is your email confirmed?).

  4. Know the routes involved

    Starter kits register all of these for you in routes/auth.php. Knowing the names helps when you customise things.

    Route nameWhat it does
    verification.notice“Check your inbox” page
    verification.verifyThe signed link inside the email
    verification.send“Resend the email” button
    password.requestForgot-password form
    password.emailSends the reset link
    password.reset / password.storeForm for the new password, and saving it

  5. Peek inside the reset logic

    The heavy lifting is done by the Password facade, called the password broker. This is a simplified version of what the kit's controller does:

    
          use Illuminate\Support\Facades\Password;

          $request->validate(['email' => ['required', 'email']]);

          $status = Password::sendResetLink($request->only('email'));

          return $status === Password::RESET_LINK_SENT
              ? back()->with('status', __($status))
              : back()->withErrors(['email' => __($status)]);

    The link's lifetime is set in config/auth.php under passwords.users.expire (60 minutes by default), and throttle stops someone spamming the button.

Common mistakes

Avoid this, do that

❌ Avoid

          MAIL_MAILER=smtp
          MAIL_HOST=smtp.realprovider.com
          # …on your laptop, with test data

Local testing with a real mailer can email actual people, or fail because the credentials are missing.

✅ Do

          MAIL_MAILER=log

Emails land in storage/logs/laravel.log: safe, instant and free.

❌ Avoid

          class User extends Authenticatable implements MustVerifyEmail
          // …but routes only use 'auth'

Emails get sent, but unverified users can still reach everything, so the feature does nothing.

✅ Do

          Route::middleware(['auth', 'verified'])->group(...);

The contract sends the email, and the verified middleware enforces it.

💡 Pro tip: find links in the log fast

Run tail -f storage/logs/laravel.log in a second terminal while you test. The verify or reset URL appears the moment the email is “sent”.

🏋️ Try it yourself
  1. Set MAIL_MAILER=log and implement MustVerifyEmail on your User model.
  2. Register a new user, find the verification link in storage/logs/laravel.log and open it.
  3. Check that email_verified_at is now filled in the users table.
  4. Log out, click “Forgot password?”, and complete a reset using the link from the log.
  5. Try the same reset link a second time. What message do you get?
Recap

Key takeaways

  • Implement MustVerifyEmail on User to send verification emails automatically.
  • Protect routes with ['auth', 'verified'] to require a confirmed email.
  • Password resets use a short-lived, single-use token stored in password_reset_tokens.
  • The Password facade (password broker) sends links and performs resets.
  • Use MAIL_MAILER=log locally, and emails appear in storage/logs/laravel.log.
