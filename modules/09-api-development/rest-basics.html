In one sentence

A REST API lets other programs work with your data by sending HTTP requests to predictable URLs and getting JSON back.

🍽️Think of a restaurant menu. The dishes are the nouns (posts, users), and what you can do with them is a short, fixed list of verbs (order, change, cancel). Every customer uses the same menu, so the kitchen always knows what you mean.

Why it matters

Your app is more than web pages

The big picture

One API round trip

A resource is any "thing" your API exposes, such as posts or comments. REST maps each action on a resource to an HTTP method plus a URL:

MethodURLMeaningTypical status
GET/api/postsList posts200 OK
POST/api/postsCreate a post201 Created
GET/api/posts/7Show one post200 or 404
PUT/PATCH/api/posts/7Update a post200 OK
DELETE/api/posts/7Delete a post204 No Content
Step by step

Think like a REST designer

Each step adds one rule. By the end you can design clean endpoints for the blog example.

  1. Nouns in URLs, verbs in methods

    URLs name things, always as plural nouns. The HTTP method says what to do with them. Never put the action in the URL.

    
          GET    /api/posts            ✅ list posts
          POST   /api/posts            ✅ create a post
          DELETE /api/posts/7          ✅ delete post 7

          GET    /api/getAllPosts      ❌ verb in the URL
          POST   /api/posts/7/delete   ❌ action in the URL

    Related things can be nested one level deep: GET /api/posts/7/comments lists the comments of post 7.

  2. Send and receive JSON

    JSON (JavaScript Object Notation) is the shared language of APIs. Clients send it in the request body and receive it in the response.

    
          {
              "id": 7,
              "title": "Hello REST",
              "body": "APIs are just URLs that return data.",
              "author": { "id": 1, "name": "Ada" },
              "created_at": "2026-10-05T09:30:00Z"
          }

    Laravel turns arrays and models into JSON automatically when you return them from a route.

  3. Use headers to talk about the format

    Headers are labels on the request. Accept: application/json tells Laravel "I want JSON back, even for errors". Content-Type says what format the body is in.

    
          curl -X POST http://127.0.0.1:8000/api/posts \
            -H "Accept: application/json" \
            -H "Content-Type: application/json" \
            -d '{"title":"Hello REST","body":"My first API post"}'
    ⚠️ Always send Accept: application/json

    Without it, a failed validation may answer with a redirect meant for browsers instead of a JSON error.

  4. Answer with the right status code

    A status code is a three-digit number that summarises the result. Clients check it before reading the body.

    200 OK
    It worked, and here is the data.
    201 Created
    A new resource was saved.
    204 No Content
    It worked, and there is nothing to return (typical after delete).
    401 Unauthorized
    You are not logged in, or your token is missing.
    403 Forbidden
    Logged in, but not allowed to do this.
    404 Not Found
    That resource doesn't exist.
    422 Unprocessable Content
    The data failed validation.

  5. Your first JSON endpoint in Laravel

    After php artisan install:api (next lesson), routes in routes/api.php get an automatic /api prefix. Returning a model or collection gives you JSON for free.

    
          <?php

          use App\Models\Post;
          use Illuminate\Support\Facades\Route;

          Route::get('/posts/{post}', function (Post $post) {
              return $post;                       // 200 + JSON, or 404 if missing
          });

          Route::post('/posts', function () {
              $post = Post::create(request()->validate(['title' => 'required']));
              return response()->json($post, 201); // 201 Created
          });
        
    
          curl http://127.0.0.1:8000/api/posts/7 -H "Accept: application/json"
Common mistakes

Avoid this, do that

❌ Avoid

          return response()->json([
              'error' => 'Post not found',
          ], 200);

A 200 with an error inside lies to the client. Its code thinks everything worked.

✅ Do

          return response()->json([
              'message' => 'Post not found.',
          ], 404);

Match the status code to the outcome, so clients can branch on it reliably.

❌ Avoid

          POST /api/createPost
          GET  /api/post/7/remove

Verbs in URLs multiply endpoints and make GET requests change data, which is dangerous.

✅ Do

          POST   /api/posts
          DELETE /api/posts/7

Plural nouns plus the right method keep the API small and guessable.

💡 Pro tip: GET must be safe

A GET request should never change data. Browsers, proxies and crawlers may repeat GET requests freely, so anything that writes belongs in POST, PUT, PATCH or DELETE.

Recap

Key takeaways

  • A REST API exposes resources at predictable URLs and speaks JSON.
  • URLs are plural nouns; HTTP methods (GET, POST, PUT/PATCH, DELETE) are the verbs.
  • Status codes summarise the result: 200, 201, 204, 404, 422 are the everyday ones.
  • Clients should send Accept: application/json to always get JSON back.
  • Laravel converts returned models and arrays into JSON automatically.
