In one sentence

Every web app is one loop: read the incoming request, decide what to do, and send back exactly one response.

☕It's like ordering at a coffee shop. You place an order (the request), the barista reads it, makes the drink (your code), and hands you a cup (the response). Then they forget you and serve the next person.

Why it matters

Everything you build fits this loop

🔄

One mental model

Pages, forms, APIs and file downloads are all “request in, response out”. Learn the loop once and every feature makes sense.

📥

Read user input safely

Laravel wraps the request in an object, so you can ask for form fields and query strings in one tidy place.

📤

Control the answer

Return a view, JSON, a redirect or a download, each with the right status code and headers.

The big picture

The journey of one request

In plain PHP you might have one file per page (about.php, contact.php). Laravel sends every URL to one file instead, and lets the router decide what runs. That way, shared jobs like sessions and security only need to be set up once.

Step by step

Work with requests and responses

These snippets use simple routes. You'll move this logic into controllers in Module 04.

  1. The simplest loop

    A route receives the request and whatever it returns becomes the response. Return a string and Laravel wraps it in a 200 OK HTML response for you.

    
          Route::get('/ping', function () {
              return 'pong';   // → 200 OK, Content-Type: text/html
          });

  2. Read the request

    Type-hint Request $request in your function and Laravel hands you the request object. It knows the URL, method, headers and every input field.

    
          use Illuminate\Http\Request;

          // Visit /search?q=laravel&page=2
          Route::get('/search', function (Request $request) {
              $term = $request->input('q');            // 'laravel'
              $page = $request->integer('page', 1);    // 2 (default 1)
              $method = $request->method();           // 'GET'
              $path = $request->path();               // 'search'

              return "Searching for {$term} on page {$page}";
          });

    input() reads from the query string and the form body, so the same code works for GET and POST.

  3. Handle a form submission

    A form POSTs its fields in the request body. You can grab one field, a few, or check whether something was sent at all.

    
          Route::post('/posts', function (Request $request) {
              $data = $request->only(['title', 'body']);

              if ($request->has('publish_now')) {
                  // ...
              }

              // Save the post (Module 05), then redirect
              return redirect('/posts');
          });
    ⚠️ Never trust input

    Anything in the request came from the user and could be anything. You'll learn to validate it properly in Forms & Validation.

  4. Choose the kind of response

    Laravel has a helper for every common answer. Each one sets the right status code and Content-Type header for you.

    
          return view('posts.show', ['title' => 'Hello']);   // HTML page, 200
          return response()->json(['id' => 42]);             // JSON, 200
          return redirect()->route('posts.index');           // 302 + Location header
          return response()->download($pathToFile);          // file download
          abort(404);                                        // stop with a 404 page

  5. Set status codes and headers yourself

    When you need full control, build the response explicitly and chain on extra details.

    
          Route::post('/api/posts', function () {
              return response()
                  ->json(['message' => 'Created'], 201)
                  ->header('X-Blog-Version', '1.0');
          });
        
    
          HTTP/1.1 201 Created
          Content-Type: application/json
          X-Blog-Version: 1.0

          {"message":"Created"}
Common mistakes

Avoid this, do that

❌ Avoid

          $title = $_POST['title'];
          echo "Saved {$title}";

Superglobals and echo bypass Laravel's request and response objects, along with their helpers and tests.

✅ Do

          $title = $request->input('title');
          return "Saved {$title}";

Read from $request and return your response so Laravel can send it properly.

❌ Avoid

          Route::post('/posts', function () {
              // save...
              return view('posts.index');
          });

Refreshing this page re-sends the POST and creates a duplicate post.

✅ Do

          Route::post('/posts', function () {
              // save...
              return redirect('/posts');
          });

Redirect after a successful POST (the Post/Redirect/Get pattern), so a refresh just re-loads a safe GET.

💡 Pro tip: dump the request

Not sure what arrived? Dump it and stop: dd($request->all()); shows every input field in a readable format.

🏋️ Try it yourself
  1. Create GET /hello that reads ?name= from the query string and returns “Hello, NAME”, defaulting to “stranger”.
  2. Create GET /api/status that returns {"ok": true} as JSON.
  3. Create GET /old-page that redirects to /hello, and confirm the 302 in DevTools.
  4. Create GET /secret that calls abort(403), and look at the page Laravel shows.
Recap

Key takeaways

  • Every request enters through public/index.php, Laravel's front controller.
  • Middleware runs on the way in and out; the router picks the code to run.
  • Type-hint Request $request to read input, the method, the path and headers.
  • Whatever you return becomes the response: a string, view, JSON, redirect or download.
  • Redirect after a successful POST to avoid duplicate submissions.
