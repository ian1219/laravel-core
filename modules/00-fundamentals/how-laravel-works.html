One order, start to finish

Press play and watch a single request walk through the shop.

Imagine someone opens https://myblog.test/posts. To Laravel, that's an order: “one list of blog posts, please”. Here is every stop it makes on the way. Press ▶ Send a request to animate it, or ⏭ Step to go one stop at a time.

🖱️
1. The customer places an orderThe browser sends GET /posts to your server. That's the order slip.
GET /posts
🚪
2. The order walks through the shop doorEvery single request enters through one door: public/index.php. There is no back entrance.
public/index.php
💡
3. Lights on, staff arrivebootstrap/app.php builds the app. Service providers (the opening crew) set up the database, cache, mail and more.
bootstrap/app.php
🛡️
4. The bouncer checks you outMiddleware runs: starts your session, checks the CSRF token, maybe asks “are you logged in?”. It can send you away right here.
middleware
🧭
5. The host reads your orderThe router looks at GET /posts, finds the matching line in routes/web.php, and walks you to the right table.
routes/web.php
🤵
6. The waiter takes overThe controller method runs. The waiter doesn't cook. They ask the kitchen for food and decide how to serve it.
PostController@index
🍳
7. The chef raids the fridgeThe Post model (the chef) asks the database (the fridge) for the latest posts. Eloquent writes the SQL for you.
App\Models\Post
🍽️
8. Plate it nicelyA Blade view turns raw data into good-looking HTML. Same pizza, now with garnish.
posts/index.blade.php
📦
9. Box it upLaravel wraps the HTML in a response with a status code (200 OK) and headers. On the way out, middleware gets one last look.
200 OK
🛵
10. Delivered!The response travels back to the browser, which draws the page. The whole trip usually takes a blink.
Illuminate\Http\Response
Remember it like this

Door → Lights → Bouncer → Host → Waiter → Chef → Plate → Delivery. Every Laravel page you'll ever build takes this same trip. Only the waiter, chef and plate change from page to page.

Four characters do most of the work you'll write yourself.

You never touch the door or the lights. Laravel handles those. The parts you write are the host's list, the waiter, the chef and the plating. Here's the host in both worlds:

🏠 Real life
🧭

The host has a seating chart: “Party asking for the posts list? Table 4, Sam is your waiter.”

=
💻 In code

        Route::get('/posts', [PostController::class, 'index']);

One line, three ideas: the method (GET, meaning “show me”), the URL (/posts), and who handles it (the index method on PostController). Why you care: when a page is broken, this file is the first place to look.

The same story in real code

Build the /posts page in four small files

Here is the exact code behind our pizza order. Each step links back to its stop in the journey above, so you can match the character to the file.

  1. 🧭 The host: a route

    Matches stop 5. The route says “for GET /posts, call PostController@index”.

    
          <?php

          use App\Http\Controllers\PostController;
          use Illuminate\Support\Facades\Route;

          Route::get('/posts', [PostController::class, 'index'])->name('posts.index');

  2. 🤵 The waiter: a controller

    Matches stop 6. The waiter asks the chef for posts and hands them to the plating station. Notice it's only three lines of real work.

    
          <?php

          namespace App\Http\Controllers;

          use App\Models\Post;

          class PostController extends Controller
          {
              public function index()
              {
                  $posts = Post::latest()->take(10)->get();

                  return view('posts.index', ['posts' => $posts]);
              }
          }

  3. 🍳 The chef: a model

    Matches stop 7. This tiny class knows its way around the posts table (the shelf in the fridge). Eloquent gives it methods like latest() and get() for free.

    
          <?php

          namespace App\Models;

          use Illuminate\Database\Eloquent\Model;

          class Post extends Model
          {
              protected $fillable = ['title', 'body'];
          }

    Behind the scenes, Post::latest()->take(10)->get() becomes this SQL. You never had to write it:

    
          select * from posts order by created_at desc limit 10

  4. 🍽️ The plating: a Blade view

    Matches stop 8. Blade is HTML with blanks. {{ }} fills a blank (and safely escapes it), and @foreach repeats a chunk for every post.

    
          <h1>Latest posts</h1>

          <ul>
              @foreach ($posts as $post)
                  <li>{{ $post->title }}</li>
              @endforeach
          </ul>

  5. 🛵 The delivery: what the browser gets

    Matches stop 10. Laravel turns the view into a full response. The browser receives plain HTML. It never sees your PHP.

    
          HTTP/1.1 200 OK
          Content-Type: text/html; charset=UTF-8

          <h1>Latest posts</h1>
          <ul><li>Hello Laravel</li><li>My first post</li></ul>
ℹ️ Where did the bouncer go?

You didn't write any middleware, but it still ran (stop 4). Every route in routes/web.php automatically gets the web group: sessions, cookies and CSRF protection. You add extra checks when you need them, like ->middleware('auth') for “members only”.

Common mix-up

Don't make the waiter cook

❌ Avoid 

          Route::get('/posts', function () {
              $rows = DB::select('select * from posts');
              $html = '<ul>';
              foreach ($rows as $r) { $html .= "<li>{$r->title}</li>"; }
              return $html . '</ul>';
          });

The host is cooking, plating and serving at once, and the title isn't escaped. It works, but it gets messy (and unsafe) fast.

✅ Do 

          Route::get('/posts', [PostController::class, 'index']);

          // PostController@index
          return view('posts.index', [
              'posts' => Post::latest()->get(),
          ]);

Each character does one job: the route points, the controller coordinates, the model fetches and the view plates.

💡 Pro tip

Lost in a project? Run php artisan route:list. It prints the host's whole seating chart: every URL and the controller that answers it.

🏋️ Try it yourself
  1. Play the pizza journey again and say each stop out loud with its real file name. No peeking at the small text.
  2. In a fresh Laravel app, add the /posts route from above and visit it. Read the error Laravel shows, then fix it by creating the controller with php artisan make:controller PostController.
  3. Create the model and its table with php artisan make:model Post -m, then run php artisan migrate.
  4. Add a second page, /about, that skips the chef entirely: a route that returns view('about'). Which journey stops did it skip?
  5. Add ->middleware('auth') to the /posts route and visit it logged out. Which character stopped you?
Key takeaways

The story in five lines

  • Every request enters through public/index.php and is set up by bootstrap/app.php.
  • Middleware is the bouncer: it checks requests on the way in and responses on the way out.
  • The router matches the method + URL to a controller using routes/web.php.
  • The controller coordinates, the model talks to the database and the Blade view builds the HTML.
  • Everything ends as a response: HTML (or JSON) plus a status code like 200.
