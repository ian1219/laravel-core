What is an API?

A waiter between your app and someone else's kitchen.

🏠 Real life
🍽️

You don't walk into the restaurant kitchen. You tell the waiter “one pizza, please”, and the waiter brings it back. You never see how it's cooked.

=
💻 In code

Your app  →  GET https://api.blog.test/api/posts/1
             (the order, sent to the waiter)

Server    →  200 OK + the post as JSON
             (the pizza, brought back)

API stands for Application Programming Interface (a fixed set of requests one program can make to another). Your weather app doesn't own satellites. It asks a weather API, and gets the forecast back.

Another way to see it: a power socket 🔌. Your toaster doesn't need to know about power stations. It just needs a plug that fits the socket. An API is the socket: a standard shape that hides everything behind the wall.

Remember it like this

An API is a waiter: you never go into the kitchen, you just place an order and get a plate back.

🍱

What is JSON?

A lunchbox where every compartment has a label.

🏠 Real life
🍱

A bento box with sticky labels: “rice”, “salad”, “dessert”. Anyone opening it knows exactly what's where, even a stranger.

=
💻 In code

{
  "id": 1,
  "title": "Hello REST",
  "published": true,
  "tags": ["laravel", "api"],
  "author": { "name": "Ana" }
}

JSON (JavaScript Object Notation) is plain text that stores data as "label": value pairs. Text goes in quotes, numbers and true/false don't, square brackets [ ] hold a list, and curly braces { } hold a smaller labelled box inside the big one.

Why do APIs love it? Every language can read it: PHP, JavaScript, Swift, Python. It's the universal lunchbox.

Remember it like this

JSON = labels + values. Curly braces are boxes, square brackets are lists.

📏

What REST adds: nouns and verbs

House rules so every API speaks the same language.

Without rules, one API might use /getAllPosts, another /fetch_post?id=1, another /deletePostNow. Chaos. REST (Representational State Transfer, a style for designing APIs) fixes this with one simple grammar:

🏠 Real life
🗣️

A sentence has a noun (the thing) and a verb (the action): “read the post”, “delete the post”.

=
💻 In code

GET     /posts/1   →  read post 1
DELETE  /posts/1   →  delete post 1

verb ↑   ↑ noun (the resource)
  • Resources are nouns in the URL. A resource is a “thing” your app manages: /posts, /users, /comments. Plural, no verbs.
  • HTTP methods are the verbs. The method (the type of request) says what to do: GET read, POST create, PUT replace, PATCH tweak, DELETE remove.
Remember it like this

The URL says what, the method says do what. If you see a verb like “get” or “delete” in a URL, something's off.

Pin this to your wall

The REST cheat sheet

Six requests cover nearly everything you'll ever do with one resource. Learn this table once and you can read most APIs in the world.

RequestWhat it doesLaravel controller methodSuccess status
GET /postsGet the list of all postsindex()🟢 200 OK
GET /posts/{id}Get one postshow()🟢 200 OK
POST /postsCreate a new poststore()🟢 201 Created
PUT /posts/{id}Replace the whole postupdate()🟢 200 OK
PATCH /posts/{id}Change just some fieldsupdate()🟢 200 OK
DELETE /posts/{id}Delete the postdestroy()🟢 204 No Content
ℹ️ PUT vs PATCH in one line

PUT sends the whole post (like repainting the entire wall). PATCH sends only what changed (like touching up one spot). Laravel routes both to update(). The next page shows the difference live.

🚦

Status codes: traffic lights for answers

A three-digit number that tells you how it went, before you even read the body.

Every response comes with a status code. The first digit is all you need to start: 2 is good news, 4 is your mistake, 5 is the server's mistake.

🟢

2xx · Green: it worked

200 OK, 201 Created, 204 No Content (done, nothing to send back).

🟡

4xx · Amber: check your order

401 who are you?, 403 not allowed, 404 not found, 422 invalid data.

🔴

5xx · Red: kitchen on fire

500 Server Error. Something broke on the server, not in your request.

Remember it like this

2 = 🙂, 4 = “you messed up”, 5 = “we messed up”.

🎟️

Stateless: the waiter has no memory

Every request must carry everything the server needs.

🏠 Real life
🐠

Imagine a waiter with a goldfish memory. Each time you order, you show your VIP wristband again, because they've already forgotten you.

=
💻 In code

GET /api/posts
Authorization: Bearer 1|aBcD3fGh...
Accept: application/json

Stateless means the server doesn't remember earlier requests. So instead of a login session, API clients send a token (a long secret string that proves who you are) in the Authorization header on every request. In Laravel, Sanctum hands out and checks these tokens.

Why bother? A forgetful waiter is easy to replace. You can run ten servers side by side, and any of them can serve any request.

Remember it like this

No token, no service. Show your wristband with every single order.

🛠️

How Laravel builds a REST API

Three moves, and the whole cheat sheet is live.

  1. Switch on API mode

    New Laravel apps don't include API routes by default. One command adds routes/api.php and installs Sanctum for tokens:

    
php artisan install:api

  2. One line, the whole cheat sheet

    apiResource registers the whole cheat sheet above, pointing each one at the matching controller method. Everything in routes/api.php automatically starts with /api.

    
use App\Http\Controllers\PostController;

Route::apiResource('posts', PostController::class);

    Run php artisan route:list to see them all. PUT and PATCH share one line, because both go to update().

  3. Return a model, get JSON for free

    No JSON-writing needed. Return an Eloquent model (or a list of them) and Laravel packs the lunchbox for you:

    
public function index()
{
    return Post::latest()->get();   // 200 + JSON list
}

public function show(Post $post)
{
    return $post;                     // 200 + JSON object
}
Spot the difference

Verbs belong in the method, not the URL

❌ Avoid 

GET  /getPosts
POST /deletePost?id=7

Made-up verbs in URLs mean every API needs its own manual.

✅ Do 

GET    /posts
DELETE /posts/7

Plural nouns plus the right HTTP method: anyone can guess what it does.

💡 Pro tip: always ask for JSON

Send the header Accept: application/json when testing. Then errors like validation failures come back as tidy JSON with a 422, instead of a redirect meant for browsers.

🏋️ Try it yourself
  1. Open https://jsonplaceholder.typicode.com/posts/1 in your browser. Name the labels in that JSON lunchbox.
  2. Write the method and URL for: “list all comments”, “delete user 5” and “fix the title of post 3”.
  3. In a fresh Laravel app, run php artisan install:api, add Route::apiResource('posts', PostController::class) and check php artisan route:list.
  4. Guess the status code: a missing post, a post created, a form with an empty title, and a successful delete.
Key takeaways

What to remember

  • An API is a waiter (or a power socket): a standard way for one program to ask another for something.
  • JSON is the labelled lunchbox data travels in: "label": value pairs, { } boxes and [ ] lists.
  • REST = nouns in URLs (/posts) + HTTP methods as verbs (GET, POST, PUT, PATCH, DELETE).
  • Status codes are traffic lights: 2xx 🟢 worked, 4xx 🟡 your mistake, 5xx 🔴 server's mistake.
  • REST is stateless: send your token with every request.
  • In Laravel: php artisan install:api, then Route::apiResource(), then return models. Want more depth? See REST Basics.
