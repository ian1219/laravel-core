In one sentence

A variable is a named box that holds one piece of data, and its data type tells PHP what kind of thing is inside.

📦Picture a moving box with a label written on the side. The label is the variable name ($title), and the contents are the value ("My first post"). You can open the box later, look inside, or swap what's in it.

Why it matters

Every program is data being moved around

🧠

Programs need memory

A user's name, a post's title, a cart total: your code has to remember things while it runs. Variables are how it remembers.

🏷️

Types prevent surprises

Knowing whether something is text, a number or "nothing" (null) stops a whole class of bugs before they happen.

🐘

Laravel is just PHP

Every controller, model and view you'll write is built from these basics. Get them solid now and Laravel reads like plain English later.

Step by step

Build your variable skills

Save each snippet as a .php file and run it with php filename.php, or paste it into an online PHP sandbox.

  1. Create and change a variable

    Every variable starts with a dollar sign $. You create one by assigning a value with =. Assign again and the old value is replaced.

    
          <?php

          $title = 'My first post';
          echo $title;          // My first post
          echo PHP_EOL;         // a line break

          $title = 'An even better post';
          echo $title;          // An even better post

    Names are case-sensitive ($title and $Title are different boxes). By convention PHP and Laravel use camelCase: $postTitle, $isPublished.

  2. Meet the core types

    PHP figures out the type from the value you assign. That's called dynamic typing: you don't declare the type up front.

    
          <?php

          $title       = 'Hello Laravel';   // string
          $views       = 1_250;             // int (underscores are just for readability)
          $rating      = 4.5;               // float
          $isPublished = true;              // bool
          $deletedAt   = null;              // null: nothing here yet

          var_dump($views);        // int(1250)
          echo gettype($rating);   // double (PHP's old name for float)

  3. Build strings: quotes, joining and interpolation

    Single quotes print text exactly as written. Double quotes also replace variables inside them with their values. That's called interpolation. The dot . joins (concatenates) strings.

    
          <?php

          $name = 'Ada';

          echo 'Hi, $name';            // Hi, $name   (single quotes: literal)
          echo "Hi, {$name}!";         // Hi, Ada!    (double quotes: interpolated)
          echo 'Hi, ' . $name . '!';   // Hi, Ada!    (concatenation)

          $greeting = 'Hello';
          $greeting .= ', world';      // append: "Hello, world"

          echo strlen($greeting);      // 12
          echo strtoupper($name);      // ADA
    💡 Wrap variables in braces

    Writing "{$name}" instead of "$name" is clearer and works for complex things later, like "{$post->title}".

  4. Do maths and compare values

    Numbers support the usual operators. Comparisons give you a bool. Always prefer strict comparison ===, which checks both the value and the type.

    
          <?php

          $price = 20;
          $qty   = 3;

          $total = $price * $qty;     // 60
          $total += 5;                // 65 (shipping)
          echo $total % 2;            // 1  (remainder)
          echo 2 ** 3;                // 8  (power)

          var_dump(5 == '5');         // bool(true)  loose: converts types first
          var_dump(5 === '5');        // bool(false) strict: int is not string
          var_dump($total >= 50 && $qty < 10);  // bool(true)

  5. Handle "maybe null" with ??

    Real data is often missing. The null coalescing operator ?? means "use the left side, unless it's null or doesn't exist, then use the right side". ??= assigns only if the variable is still null.

    
          <?php

          $nickname = null;

          echo $nickname ?? 'Guest';     // Guest

          $theme = null;
          $theme ??= 'dark';             // only set if still null
          echo $theme;                   // dark

          var_dump(is_null($nickname));  // bool(true)

  6. Lock values with constants and turn on strict types

    A constant is a value that never changes. It has no $ and is written in UPPER_CASE. Adding declare(strict_types=1); at the very top of a file tells PHP to stop silently converting types when you call typed functions, so mistakes fail loudly.

    
          <?php

          declare(strict_types=1);

          const SITE_NAME = 'Laravel Blueprint';
          const MAX_POSTS_PER_PAGE = 15;

          echo SITE_NAME;

          // Converting on purpose ("casting"):
          $pageFromUrl = '3';
          $page = (int) $pageFromUrl;    // 3 as an int
    ℹ️ Where types really shine

    You'll add types to function parameters in Functions and to class properties in Classes & Objects. That's where strict_types starts catching bugs for you.

Common mistakes

Avoid this, do that

❌ Avoid

          if ($status == 0) {
              // '0', false, null and '' can all sneak in
          }

Loose == converts types before comparing, which leads to strange matches.

✅ Do

          if ($status === 0) {
              // only the integer 0 gets in
          }

Strict === checks value and type, so you get exactly what you asked for.

❌ Avoid

          $x = 'Ada';
          $d = 3;
          echo 'Hello $x, you have $d posts';

Vague names, and single quotes print $x literally instead of its value.

✅ Do

          $authorName = 'Ada';
          $postCount  = 3;
          echo "Hello {$authorName}, you have {$postCount} posts";

Descriptive camelCase names plus double quotes with braces read clearly and work.

💡 Pro tip: dump and die

In plain PHP, var_dump($x); exit; shows a value and stops. In Laravel you'll use the shortcut dd($x) ("dump and die") constantly while debugging.

ℹ️ Where you'll see this in Laravel
  • Your .env file is a list of named settings like APP_NAME, and Laravel reads them as strings, ints and bools.
  • Route parameters such as {id} arrive as strings (see Routing).
  • ?? is everywhere: $request->input('page') ?? 1, $post->subtitle ?? 'Untitled'.
  • A model's nullable column, like published_at, comes back as null when it's empty (see Models).
Recap

Key takeaways

  • Variables start with $, use camelCase, and are case-sensitive.
  • The core types are string, int, float, bool and null.
  • Double quotes interpolate ("{$name}"); single quotes don't; . joins strings.
  • Use strict comparison === almost always.
  • ?? and ??= give clean fallbacks for missing values.
  • Constants never change; declare(strict_types=1); makes type mistakes fail loudly.
