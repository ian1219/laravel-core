In one sentence

A class is a blueprint that describes some data and the actions on it, and an object is one real thing built from that blueprint.

🍪A class is a cookie cutter; objects are the cookies. One cutter (Post) can stamp out as many cookies as you like, and each cookie can have its own sprinkles (its own title, its own views).

Why it matters

Almost every Laravel file is a class

🧺

Data and behaviour together

A Post object holds its title and knows how to publish itself. No more loose arrays and scattered functions.

🏗️

Laravel is built of them

Models, controllers, middleware, jobs, mailables: open any file in app/ and you'll find class at the top.

🧭

Your editor understands you

Step by step

Build your first classes

We'll grow a small Post class for our blog, one idea at a time.

  1. Define a class and create objects

    A class has typed properties (its data) and methods (its actions). new creates an object, and the object operator -> reaches into it.

    
          <?php

          class Post
          {
              public string $title = '';
              public int $views = 0;

              public function addView(): void
              {
                  $this->views++;
              }
          }

          $post = new Post();
          $post->title = 'Hello Laravel';
          $post->addView();

          echo $post->views;   // 1

    Inside the class, $this->views means "this particular object's views". Class names use PascalCase and, by convention, live in a file with the same name.

  2. Set up objects with a constructor

    The constructor __construct() runs automatically when you call new. It's where an object gets its starting data, so it's never half-built.

    
          class Post
          {
              public string $title;
              public string $author;

              public function __construct(string $title, string $author)
              {
                  $this->title = $title;
                  $this->author = $author;
              }
          }

          $post = new Post('Hello Laravel', 'Ada');

  3. Shorten it with constructor property promotion

    That pattern is so common that PHP 8 added constructor property promotion: put the visibility keyword in front of a constructor parameter and PHP declares and assigns the property for you. This is what modern Laravel code looks like.

    
          class Post
          {
              public function __construct(
                  public string $title,
                  public string $author,
                  public int $views = 0,
                  public ?string $subtitle = null,
              ) {}

              public function summary(): string
              {
                  return "{$this->title} by {$this->author} ({$this->views} views)";
              }
          }

          $post = new Post(title: 'Hello Laravel', author: 'Ada');
          echo $post->summary();   // Hello Laravel by Ada (0 views)

    Notice the named arguments from Functions working with new too.

  4. Class-level members: constants and static

    Some things belong to the class itself, not to any one object. Access them with :: (the "scope resolution operator") instead of ->. A static method is often used as a friendly "named constructor".

    
          class Post
          {
              public const MAX_TITLE = 120;

              public function __construct(public string $title) {}

              public static function draft(): static
              {
                  return new static('Untitled draft');
              }
          }

          echo Post::MAX_TITLE;          // 120
          $draft = Post::draft();        // static call, no object needed first
          echo Post::class;              // "Post" (the full class name as a string)

  5. Objects inside objects, and the nullsafe operator

    Properties can hold other objects. When one of them might be null, the nullsafe operator ?-> stops the chain and returns null instead of crashing.

    
          class Author
          {
              public function __construct(public string $name) {}
          }

          class Comment
          {
              public function __construct(public string $body, public ?Author $author = null) {}
          }

          $anon = new Comment('Great post!');

          echo $anon->author?->name ?? 'Anonymous';   // Anonymous
          // $anon->author->name would be an Error: reading a property on null

  6. A fixed set of choices: enums and match

    An enum (PHP 8.1+) is a special class with a fixed list of allowed values, called cases. A backed enum gives each case a string or int, perfect for saving to a database. match is a strict, expression-based switch that returns a value.

    
          enum PostStatus: string
          {
              case Draft = 'draft';
              case Published = 'published';
              case Archived = 'archived';

              public function label(): string
              {
                  return match ($this) {
                      PostStatus::Draft     => '📝 Draft',
                      PostStatus::Published => '✅ Live',
                      PostStatus::Archived  => '📦 Archived',
                  };
              }
          }

          $status = PostStatus::from('published');   // from a DB string
          echo $status->label();                     // ✅ Live
          echo $status->value;                       // published
          PostStatus::tryFrom('oops');               // null instead of an error
    ℹ️ Why not just use strings?

    With a plain string, 'pubished' (a typo) slips through. A parameter typed PostStatus $status only accepts real cases, and match throws an error if you forget to handle one.

Common mistakes

Avoid this, do that

❌ Avoid

          public function addView(): void
          {
              $views++;   // undefined variable
          }

Inside a method, a bare $views is a local variable, not the property.

✅ Do

          public function addView(): void
          {
              $this->views++;
          }

Always go through $this-> to read or change the object's own properties.

❌ Avoid

          $post = new Post();
          $post->title = 'Hi';
          // forgot the author... object is half-built

Setting required data one property at a time makes it easy to forget something.

✅ Do

          $post = new Post(title: 'Hi', author: 'Ada');

Require it in a promoted constructor. The object is valid from the moment it exists.

💡 Pro tip: one class per file, autoloaded

In real projects you never require class files by hand. Composer's autoloader finds App\Models\Post in app/Models/Post.php automatically, as long as the namespace and folder match.

🏋️ Try it yourself
  1. Create a Product class with promoted properties name, price (float) and stock (int, default 0).
  2. Add a method isAvailable(): bool that returns whether stock is above zero.
  3. Add a static method free(string $name): static that creates a product with price 0.
  4. Create an enum Size: string with Small, Medium and Large, plus a label() method using match.
  5. Give Product a ?Size $size = null property and print $product->size?->label() ?? 'One size'.
ℹ️ Where you'll see this in Laravel
  • Models: class Post extends Model is a class, and each database row becomes an object (see Models).
  • Controllers: classes whose methods answer requests (see Controllers).
  • Constructor promotion is how services receive their dependencies: public function __construct(private Mailer $mailer) {}.
  • Enums can be cast on model attributes, so $post->status comes back as a PostStatus case.
  • Nullsafe chains like $post->author?->name are common in Blade views.

Recap

Key takeaways

  • A class is a blueprint; new creates an object (instance) from it.
  • Properties hold data, methods hold behaviour, and $this means "this object".
  • Constructor property promotion declares and assigns properties in one line.
  • -> works on objects; :: works on the class itself (constants, static methods).
  • ?-> safely walks a chain that might hit null.
  • Enums model a fixed set of values; match maps each one to a result.
